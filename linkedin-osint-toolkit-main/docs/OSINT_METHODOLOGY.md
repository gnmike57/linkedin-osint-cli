# OSINT Methodology: Company Discovery on LinkedIn

This guide describes how to discover companies in any region and map them to LinkedIn pages for OSINT/security research at scale:

***

## 1. Overall strategy

For OSINT at scale, separate the problem into two stages:

1. **Build a seed list of target region companies** (from sources that are easier to harvest than LinkedIn itself).
2. **Enrich that list with LinkedIn company URLs** using search engines / enrichment APIs, *not* direct LinkedIn scraping (because of ToS and technical friction).

This is much more robust than trying to “discover” everything directly inside LinkedIn.

***

## 2. Stage 1 – Building a seed list of target region companies

### 2.1. Public and semi-public directories

Look for sources that either:

- Allow CSV export / API, or
- Are regular websites that can be scraped once with low frequency.

Typical examples (adapt to your target region):

- **Startup / tech ecosystems**
    - National/startup portals and innovation authority portals
    - VC portfolios with strong regional focus and their portfolio pages
    - Cybersecurity-specific maps / ecosystems and industry association lists
- **Business / company registries**
    - Corporate / company registrar search (for legal entities – may not always map 1:1 to a LinkedIn page, but good coverage)
    - Industry associations (chambers of commerce, export institutes, tech alliances, etc.)
- **Tech/event resources**
    - Conference sponsor lists for regional security / tech conferences
    - Accelerator / incubator cohorts

For each source, your goal is to extract at least:

- `company_name`
- `website`
- Optional: `sector`, `city`, `founded_year`, etc.

Store it in a master table (CSV/DB).

***

## 3. Stage 2 – Mapping companies → LinkedIn pages (enrichment)

Once you have a list of company names (and ideally domains), you can systematically resolve their LinkedIn URLs.

### 3.1. Manual / semi-manual pattern (to understand the logic)

For a *single* company:

1. **Google/Bing dork**:
    - `site:linkedin.com/company "Company Name" "Target Region"`
    - If you have the domain: `site:linkedin.com/company "Company Name" "example.com"`
2. **Check result structure**: company pages usually look like:
    - `https://www.linkedin.com/company/<slug>/`
3. **Disambiguate**:
    - Prefer results where the snippet or title mentions your target region or a known city
    - If there are multiple hits, use the domain in the snippet ("example.com") as tie-breaker

This manual logic is exactly what you’ll later automate.

***

## 4. Automating the lookup (thousands of entries)

You have three main automation-friendly patterns:

### 4.1. Search-engine-based enrichment (most common)

High-level algorithm (pseudo-workflow):

1. Input: table `companies` with `company_name`, `website`.
2. For each row, build a search query string, for example:
    - `"site:linkedin.com/company" + " " + company_name + " " + "Target Region"`
    - If `website` exists, add it as another term.
3. Send the query to a **search API** (Google Custom Search, Bing Web Search, SerpAPI, etc.).
4. From the first 3–5 results, pick URLs under `linkedin.com/company`.
5. Store:
    - `linkedin_url`
    - confidence score (basic heuristic: rank, presence of website, location mention).

Important notes:

- Do **not** hammer LinkedIn directly with scraping; do this through search engines or a compliant search-API provider.
- Respect rate limits and ToS of the search API you choose.
- Add basic error handling and retry logic.

Given your background, implementing this in Python with `requests` + chosen search API + some HTML/JSON parsing should be straightforward.

***

### 4.2. Using enrichment services (if budget allows)

If you can pay for services and want reliability:

- Tools like **Clearbit**, **ZoomInfo**, **RocketReach**, etc. often provide:
    - Input: `domain` or `company_name`
    - Output: structured company profile that includes LinkedIn URL.

Workflow:

1. Build your target region company list with domains.
2. Feed domains into the enrichment API in batches.
3. Save the returned `linkedin_url`.

Pros:

- Very high match quality and less custom code.
Cons:
- Cost, and you are depending on a third-party vendor.

***

### 4.3. LinkedIn internal search – only for low volume / tactical checks

For OSINT validation or special targets (not thousands):

- Use **LinkedIn’s own search UI**:
    - Search by company name.
    - Filter by location: your target region.
    - Manually verify the page: logo, website URL, HQ location.

This is good for:

- Spot-checking matches generated by your automated pipeline.
- Investigating specific high-value targets more deeply.

But:

- Do not attempt to script this directly; it is fragile and usually against ToS.

***

## 5. Identifying companies in your target region

Since many companies are multinational, you need rules for what "target region" means in your context. For OSINT / security research typical heuristics:

- Company page says **"Headquarters: [Target City/Region]"**
- Or: founded in target region / majority operations in target region
- Or: R&D center in target region and appears in regional tech directories / ecosystems

From an automated perspective, you can:

- Check external sources:
    - If the company is on multiple region-specific lists or has region-specific domain, flag as target
- For LinkedIn snippets:
    - In search results, prefer pages whose snippet contains target region or known cities

You can encode this as a scoring function:

- +2 if snippet contains target region name
- +2 if snippet contains a known city in target region
- +3 if snippet shows company website equal to your `website` field
- Choose the URL with highest score above a threshold

***

## 6. Practical search patterns you can use today

### 6.1. For manual discovery

In Google/Bing:

- **All companies in a region on LinkedIn** (broad):
    - `site:linkedin.com/company "United States" "Headquarters"`
    - `site:linkedin.com/company "New York" OR "San Francisco" OR "Austin"`
- **Sector-specific**:
    - `site:linkedin.com/company "cybersecurity" "United States"`
    - `site:linkedin.com/company "fintech" "Germany"`

You can use these queries to:

- Manually explore and understand how LinkedIn structures pages.
- Collect small sectoral lists before scaling up.


### 6.2. For semi-automated scripts

For each company:

- Query template:
    - `q = f'site:linkedin.com/company "{company_name}" "{country_or_city}"'`
- Hit your chosen search API with `q`.
- Parse results → save LinkedIn URL candidates.

***

## 7. Suggested concrete workflow for you

Given you want *thousands* of entities and have strong technical skills:

1. **Choose 2–3 good data sources for your target region** as seeds
Example: one startup/tech portal, one cyber/sector map, one government/registrar source
2. **Write a scraper / downloader**:
    - Extract `company_name`, `website`, `sector`, `hq_city`.
    - Store in a local DB/CSV.
3. **Implement search-enrichment microservice**:
    - Input: company record.
    - Output: `linkedin_company_url`, `confidence_score`.
    - Internally use Google/Bing/SerpAPI style search.
    - Include logic to:
        - Prefer results with matching domain
        - Fall back to best region / city matches
4. **Run enrichment in batches** with rate limiting.
    - Parallelize modestly (threads/processes) respecting API quota.
5. **Validate sample**:
    - Take random samples of matches across score buckets.
    - Manually verify using browser + LinkedIn UI.
    - Tune your heuristics until precision is acceptable.
6. **Feed results into your OSINT / TI pipeline**:
    - Once LinkedIn URLs are attached, you can pivot to:
        - Employee enumeration (again carefully, ToS-aware).
        - Tech stack clues from company descriptions.
        - Org structure, subsidiaries, etc.
